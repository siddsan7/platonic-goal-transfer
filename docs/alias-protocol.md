**Protocol frozen before the first alias experiment.** Code: `src/pgt/alias_study/study.py`.

## Question

Four nonce words (`vexlo`, `trumbik`, `olquen`, `sprindt`) appear nowhere in the visual training,
the calibration captions or the original vocabulary. Each nonce is linked to the ordinary glyph
words only through synthetic caption pairs (text only). The study compares two encoders trained on
those pairs:

- **aligned**: the pairs consistently link each nonce to one glyph;
- **independent**: the pairs link each nonce to all four glyphs equally.

The question is whether the aligned encoder places the calibrated goal for a nonce caption closer
to the target pad's goal image than the independent encoder does. The planner receives each calibrated goal vector. We use that same vector to measure the
distance margin on a rendered board.

## How this differs from the withheld-combinations follow-up

- The follow-up asked whether known words transfer to glyph–trim combinations withheld from text.
  This study asks whether entirely **new tokens** inherit a glyph's meaning.
- The only source of that meaning is **text-only synthetic pairing**. Calibration never sees a
  nonce, so the image side has no direct label for one.
- The link pairs include canonical captions for all 16 glyph–trim combinations. This is text only;
  it does not change the earlier study's calibration rule.

## Fixed design (all constants live at the top of `study.py`)

- **Alias mappings.** Two blocks, seeded 5101 and 5102. The first block draws a random glyph permutation.
  The second draws uniformly from the permutations outside the first rotation class. Each
  contributes its four Latin rotations. Within a block every alias maps to every glyph
  exactly once. That gives eight distinct mappings, and the rotations are not independent draws.
- **Arms per mapping.** All three arms (aligned, independent, untrained) start from one cloned
  initialisation (rng `[1, 7103, mapping]`). The untrained arm is that initialisation with no
  training. A **raw** bag-of-words arm goes through the same calibration probe.
- **Text pairs.** Both trained arms get the follow-up's clean corpus for corpus seed 1, counted,
  with duplicates kept as weights rather than dropped. Each arm also gets bidirectional
  cross-template links over 4 aliases × 4 trims:
  - alias caption (template a) → canonical caption (template b);
  - canonical caption (a) → alias caption (b).

  The trim stays the same within each link. Every alias, trim and direction gets four links.
  In the aligned arm the correct glyph appears four times. In the independent arm each of the four
  glyphs appears once. The left and right marginals, the total weight, the vocabulary, the
  architecture (16 wide), the optimiser and the maximum number of epochs are identical across trained arms. Training can stop early.
- **Vision and calibration.** The follow-up visual model is rebuilt with `fitting.fit_vision`
  (same design, same exclude set). Calibration bank 1 from `fitting.anchor_bank` (64 seen-combination
  anchors) is then drawn from that same exclude set. Every arm and the raw arm fit their own
  centred ridge on those 64 canonical captions with the same penalty, so a nonce never appears in
  calibration. Because of that, the raw probe's nonce coefficients are exactly zero, and the raw
  arm gives competing aliases bit-identical goals.
- **Boards.** The first 12 of the 48 published follow-up test topologies (`test/0` … `test/11`),
  regenerated by the frozen bank code. This bank was already evaluated and published, so the
  result is a **conditional paired diagnostic**, not a fresh held-out test. `plan.json` records
  the exact walls, start and pads before any fitting.
- **Queries.** These follow the follow-up's layout. Every board gets every trim, both the seen and
  the withheld panel (so all 16 combinations appear), both pad orders, both held-out query
  templates and both goals. That makes 64 queries per board.

## Measurements

- **Margin**: ‖v − foil image‖² − ‖v − target image‖². Here v is the exact calibrated goal vector
  handed to the frozen planner, and the images come from the frozen visual model on the actual
  rendered board. A positive margin favours the target.
- **Primary**: the paired mean of aligned − independent nonce margins. Boards, mappings and queries
  are equally weighted (mean over queries, then over mappings, then over boards). It comes with a
  95% percentile bootstrap over the 12 boards (2,000 resamples, seed 20261121). That interval is
  conditional on the fixed lexicons, the calibration bank and the one visual fit.
- **Secondary**:
  - aligned − untrained nonce margin;
  - executed paired success, aligned − independent and aligned − untrained;
  - first-terminal outcomes (correct, wrong pad, timeout) for nonce and canonical captions in every
    arm, untrained included, so that beating the deliberately blind raw arm is never read as
    learning.
- **Execution.** Each episode is a real rollout through `engine.run_planned` with a bounded frame
  cache. The planner receives only the rendered current frame, the goal vector and the steps
  left. No evaluation metadata reaches it.

## Validity checks (pre-declared; any failure → `INVALID`, and no contrast is reported)

1. Every distance and margin is finite, each margin equals d_foil − d_target, and the reported paired mean differences fit in a finite number.
2. Image-goal executed success is at least 80%.
3. Canonical (ordinary-word) executed success is at least 80% in the aligned arm and at least 80%
   in the independent arm (pooled over mappings).
4. The raw arm is exactly blind. Its nonce coefficients are zero and the four aliases give equal
   goal vectors (checked on vectors at run time). Raw nonce distances are also equal across
   mappings for every query (recomputed from rows).
5. Coverage is complete: every expected (board, query, mapping, arm, kind) key appears once,
   plus one image row per query. Missing, extra or duplicate keys → `INCOMPLETE`.

A run ends in one of four statuses:

| Status | Meaning |
| --- | --- |
| `VALID` | All checks pass |
| `INVALID` | A validity check failed; no interpretation is given |
| `INCOMPLETE` | The budget was exceeded, the process was killed, or coverage is incomplete |
| `FAILED` | An exception occurred; it is recorded and re-raised |

## Outputs (one fresh directory per run; an existing `--out` is refused)

- `plan.json` records the board selection and the eight mappings. It is written before any
  fitting.
- `rows.jsonl.gz` holds the rows, gzip with mtime 0. Each row has: split, board, panel, trim,
  order, template, query, target, foil, mapping, arm, kind (nonce, canonical or image), word,
  d_target, d_foil, margin, outcome and steps.
- `summary.json` holds:
  - status;
  - the Git commit and dirty flag;
  - every setting, the vocabulary and the follow-up design digest;
  - plan and rows SHA-256;
  - coverage, rates, diagnostics, primary, secondary and bootstrap.

## Reproduction (local CPU only, no network)

```sh
git status --porcelain      # must be empty; run refuses a dirty tree unless --allow-dirty (recorded)
timeout 300 python -m pgt.alias_study run --out runs/alias-transfer-01
python -m pgt.alias_study verify --out runs/alias-transfer-01
```

Prefix the commands with `PYTHONPATH=src` if the package is not installed. `timeout` is GNU
coreutils; it is also available in Git Bash on Windows. Inside the process a cooperative 270 s
budget is checked between stages and scenes. The outer 300 s timeout is the hard limit. If the run
is killed, `summary.json` stays `INCOMPLETE`.

Run time has not been measured, because the implementation phase fitted no model. If 300 s is not
enough, the honest result is `INCOMPLETE`. Do not rerun with different boards or seeds to get a
different outcome.

`verify` recomputes coverage, rates, diagnostics, primary, secondary, bootstrap and the rows digest
from the rows. It also checks the board selection, mapping schedule, per-row labels and raw target/foil symmetry. Unavailable distances are stored as JSON null and invalidate the comparison. The vector-level raw check is read from the summary because vectors are not stored.

## Prior context (descriptive only)

- Tian et al., *What Makes for Good Views for Contrastive Learning?*, NeurIPS 2020. They describe
  how the information shared between paired views shapes what a contrastive objective learns. Here,
  the link pairs are the only place a nonce shares information with a glyph word. The independent
  arm removes that shared information while keeping the marginals. [NeurIPS paper](https://proceedings.neurips.cc/paper/2020/hash/4c2e5eaae9152079b9e95845750bb9ab-Abstract.html)
- Xue et al., *Which Features are Learnt by Contrastive Learning? On the Role of Simplicity Bias in
  Class Collapse and Feature Suppression*, ICML 2023. They analyse which features contrastive
  training keeps or suppresses. [ICML paper](https://proceedings.mlr.press/v202/xue23d.html)

Neither paper makes a prediction about this setup, and none is claimed.
